No controller changes. No cloud relay. GET is the only HTTP method in the source.

THE PROBLEM

A screenshot is not network documentation.

UniFi's topology is a pan-and-zoom canvas inside a fixed viewport. A full-page capture only gets the visible region; zooming out enough to fit a real network makes its labels useless. unifi-map reads the same local JSON data the console uses and renders the result properly.

CHOOSE THE RIGHT OUTPUT

One topology, useful in more than one place.

SVG · PDF · PNG

Portable diagrams for zooming, printing, and the places that insist on an image.

draw.io

Editable shapes, already positioned, ready to rearrange and annotate.

HTML

A self-contained explorer for busy maps: pan, zoom, search, trace a client path, and collapse leaves.

DOT · Mermaid · JSON

Graphviz source, Markdown-native diagrams, and a stable normalized topology for programs.

DESIGNED FOR REAL NETWORKS

Keep the useful details. Make uncertainty visible.

  • Uses real Ubiquiti device artwork when available, with built-in offline fallbacks.
  • Includes clients, not only the infrastructure skeleton.
  • Lets you assert links and correct controller mistakes without passing claims off as observations.
  • --obfuscate replaces names, addresses, MACs, SSIDs, VLAN names, and ISP details while preserving the topology.

START WITHOUT CREDENTIALS

Map a support file instead of a controller.

Generate a UniFi support file, then render it locally. No API key is needed, and the command below makes no network request. 

unifi-map all --support-file support-XXXX.tgz --offline --icons builtin
